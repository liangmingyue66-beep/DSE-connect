# 查询质量优化方案（2026-10-17）

> 起因：用户实测"我成绩434，选修物理化学，有没有985学校推荐给我" → 返回 0 条，且模型自编分数表格。

## 一、三个问题现象

1. **不加省份查不到？** —— 用户问"985学校推荐给我"（未指定省份），返回 0 条，模型解释"你尚未指定省份"。
2. **0 条的说明误导** —— 模型只说"工具暂未返回匹配的录取记录"，用户可能误解为"没有这几所学校/没有录取记录"。
3. **"手动切换策略"** —— 模型声称"工具未响应，我手动切换策略"，并给出中山/华工的分数表格。

## 二、根因（已技术验证）

**跟省份无关！985 + 434（无省份）实际有 68 条。**

复现用户原话，模型实际调用参数：

```json
{"scores": ["4","3","4"], "tier": "985", "major_keyword": "理工"}
```

**"理工"是模型幻觉出来的参数**（用户只说了"985学校"，没提"理工"）。`LIKE '%理工%'` 在专业名里匹配不到任何东西 → 0 条。

问题 3 的表格数字（"中英数444起""4中英3数4通识3"）**全是模型凭训练记忆编的**（工具返回空，它自己填）——这是最危险的幻觉。

三个问题归为两个根因：
- **根因 A**：模型乱填参数（幻觉出用户没说的专业词）；
- **根因 B**：工具返回 0 条时，模型既不解释清楚、还凭记忆编数据。

## 三、解决方案（A + B + C）

### 方案 A：防参数幻觉
1. 系统提示 + 工具 docstring 强调："只填用户明确提到的参数，不要自己加专业词"；
2. `query_schools` 过滤**宽泛词**（理工/工科/理科/文科/商科…）——这些不是具体专业，匹配不到，直接忽略而不是当筛选条件。

### 方案 B：0 条时给诊断信息
`query_schools_tool` 返回 0 条时，自动再算"去掉专业词后"的条数，一起返回：
```json
{"total": 0, "hint": "当前条件无结果；去掉专业词限制后该范围有 68 条（最低分 11 起）"}
```
让模型能说清"不是没有，是某个条件太窄"。

### 方案 C：禁止 0 条时编造（最关键）
1. 系统提示 + 空结果的工具返回里，明确"必须如实说没查到，禁止用记忆补充学校名/分数"；
2. **answer_guard 增强**：工具结果 `total=0`，但回答里出现具体分数（正则 `\d+\s*分`）→ 判定编造 → 强制重查（提醒"0 条，禁止编造"）。

## 四、验证计划

- 新增评测用例：`"我成绩434选修物理化学，有没有985学校推荐给我"` → 断言：回答**不含**具体分数数字（`\d+分`），且含"没查到/建议放宽"类表述；
- 复测原 20 条不回归。
