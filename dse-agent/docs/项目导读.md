# 项目导读：怎么读这个项目

> 给自己（也給面试官）的一份地图。先看整体怎么转，再看每个文件干什么，最后按顺序读。

## 一、一句话定位

**DSE 志愿填报助手**：帮香港 DSE 考生查内地高校录取数据 + 招生政策。核心不是"能聊"，而是**数据可追溯、不编造**——模型只做"理解人话 + 说人话"，查数据/查政策都由确定性代码完成。

## 二、技术栈

| 层        | 用什么                                            |
| -------- | ---------------------------------------------- |
| Agent 编排 | LangGraph（ReAct 循环：agent ⇄ tools）              |
| 工具绑定     | LangChain `@tool` + `bind_tools`               |
| 后端       | FastAPI + SSE（节点级 + token 级流式）                 |
| 数据       | PostgreSQL（165 校 + 3794 专业）                    |
| 向量检索     | DashScope `text-embedding-v3` + 内存余弦相似度        |
| LLM      | Qwen `qwen-plus`（主）/ DeepSeek（备），temperature=0 |

## 三、数据流转链路（一次对话的全流程）

```
用户在网页输入「我434想去广东读计算机」
  │
  ▼ ① 前端 fetch POST /chat
frontend/src ────────────────────────→  app/server.py（FastAPI）
                                                    │
                                                    ▼ ② 启动 ReAct 循环
                                          app/graph.py  graph.stream(
                                          stream_mode=["updates","messages"])
                                                    │
                              ┌─────────────────────┴─────────────────────┐
                              ▼                                            │
                    agent 节点（LLM 决策）                                   │
        输入：系统提示 prompts/agent/v1.0.0.md + 历史 + 工具结果                │
        输出：① 要调工具（tool_calls） ② 要回答（文本）                          │
                              │                                            │
              ┌───────────────┴───────────────┐                            │
              ▼ 要调工具                       ▼ 要回答                        │
      tools 节点                     answer_guard（护栏）                     │
  执行模型指定的工具               含分数但没查库？→ 强制重查                  │
      │                                │                                   │
      ├─ query_schools_tool ──→ app/tools/query_schools.py ──→ PostgreSQL    │
      │      （确定性 SQL：筛选/排序/分档/页码）                              │
      │                                                                     │
      └─ search_policy_tool ──→ app/tools/search_policy.py                   │
             └─→ app/retriever.py ──→ DashScope embedding + 余弦检索 ──→ data/policy/*.md
                              │                                            │
                              └──────────── 结果喂回 agent（循环）──────────┘
                                                    │
                                                    ▼ ③ 逐 token / 逐节点推 SSE
                                          前端逐字渲染（frontend/src）
```

**三条数据来源，各管一摊：**

- **录取数据**（只读）：PostgreSQL，由 `query_schools` 确定性查询，模型碰不到原始数据；
- **政策语料**（只读）：`data/policy/` 三份官方文件，向量检索后交给模型组织；
- **对话记忆**（可写）：`memory.last_slots`，跨轮保存查询条件（增量继承，防抄错）。

## 六、关键设计点（面试可直接讲）

1. **LLM 不计算、不写 SQL**：模型只做"意图翻译 + 自然语言转述"，筛选/排序/分档/页码全由确定性代码做。这是"数据可信"的根基。
2. **混合架构**：ReAct 外壳（对话灵活、能追问/换条件）+ 确定性工具内核（数据准确）。不是"全自动 Agent"，是"该自由的自由、该锁死的锁死"。
3. **防编造护栏（answer_guard）**：回答含分数但全程没查库 → 判定编造 → 强制重查。评测证明它把对抗用例从 1/4 拉到 4/4。
4. **跨轮记忆防抄错**：`memory.last_slots` 增量继承——模型只填"本轮新说的"，历史值由代码补全（避免模型回忆数字抄错，如 434→454）。
5. **可观测**：trace_id 贯穿 + 结构化日志（每次 LLM 调用/工具调用的耗时、token）。出问题能定位，不是黑盒。
6. **评测驱动**：22 条评测集（正常 11 / 边界 7 / 对抗 4），每次改代码跑一次，防回归。
7. **成本护栏**：max_steps=5（防死循环）+ token 预算（防异常烧钱）+ 优雅停止。

## 七、启动命令速查

```bash
# 网页版（推荐）
cd E:\DSE Connect\dse-agent
.venv\Scripts\python.exe -m uvicorn app.server:app --port 8000
# 浏览器开 http://localhost:8000

# 命令行版
.venv\Scripts\python.exe app/main.py

# 单元测试
.venv\Scripts\python.exe -m pytest tests/ -q

# 评测（全量约 3 分钟）
.venv\Scripts\python.exe eval/run_eval.py
.venv\Scripts\python.exe eval/run_eval.py --category adversarial   # 只跑对抗
```

**依赖配置**：`.env` 里需要 `DASHSCOPE_API_KEY`（Qwen + embedding）、`DEEPSEEK_API_KEY`（备选）、`DB_*`（PostgreSQL）。
