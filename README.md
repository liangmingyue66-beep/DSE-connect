# DSE 志愿填报助手

面向香港 DSE 考生的内地升学志愿填报助手。把《内地高校招收香港中学文凭考试学生指南》的 PDF 转成**可对话查询的数据服务** —— 覆盖 165 所内地高校、3794 条专业录取记录。

核心不是"套一个大模型"，而是**让模型不碰数据**：分数由参数化 SQL 查，政策从原文检索，模型只负责理解问题和组织语言。

```
用户：我 434 想去广东读计算机
助手：查得 6 条可报专业 —— 中山大学（计算机类，最低 13 分，低你 2 分·稳）、
      华南理工大学（计算机学院，最低 12 分）…（附书页页码可回查）
```

## 功能

- **查分数线**：按省份 / 城市 / 院校层次 / 专业关键词 / 三科成绩筛选，返回最低分、最高分、书页页码
- **问政策**：报名时间、志愿规则、校长推荐计划等，回答**带原文出处**
- **多轮对话**：支持"那北京呢""去掉分数限制"这类增量追问，条件由代码精确维护
- **多会话管理**：侧边栏切换 / 新建 / 删除，每个会话独立上下文

## 技术栈

`Python 3.11` · `FastAPI` · `LangGraph`（ReAct）· `LangChain` · `PostgreSQL` · `RAG`（Embedding + 余弦检索）· `SSE` 流式 · `Vue 3` + `Vite`

## 架构

```
用户 ──▶ FastAPI (SSE 流式)
           │
           ▼
     LangGraph ReAct 循环
     ┌─────────────────────────────┐
     │  agent ──▶ tools ──▶ agent  │  模型决定查什么，代码负责怎么查
     │    │                        │
     │    ▼                        │
     │  answer_guard ──▶ 输出      │  回答前校验：是不是在编？
     └─────────────────────────────┘
           │                    │
           ▼                    ▼
   query_schools_tool    search_policy_tool
   （参数化 SQL）          （政策 RAG）
           │                    │
           ▼                    ▼
      PostgreSQL          政策语料（带出处）
```

三个关键设计：

| 设计 | 解决什么 |
|---|---|
| **确定性工具 + 模型转述** | 模型只输出结构化参数，筛选排序全部由 SQL 完成 —— 分数不由模型生成 |
| **answer_guard 护栏** | 检测"用户问分数、却没查库、回答却有具体分数"时强制重查（最多 2 次） |
| **分层记忆** | 模型只输出本轮增量，代码维护精确查询条件 —— 避免模型复述历史时抄错数字 |

## 快速开始

**前置**：Python 3.11+、PostgreSQL 14+、Node 18+（前端构建用）

```bash
# 1. 安装依赖
cd dse-agent
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. 配置（需要自行申请 API Key）
cp .env.example .env
#   DASHSCOPE_API_KEY  阿里云百炼（主模型 qwen-plus + embedding）
#   DEEPSEEK_API_KEY   DeepSeek（主模型失败时自动降级）
#   PG_*               PostgreSQL 连接信息

# 3. 建库灌数据（启动时自动建表）
python scripts/load_data.py

# 4. 构建前端 + 启动
cd frontend && npm install && npm run build && cd ..
python -m uvicorn app.server:app --port 8000
```

打开 http://localhost:8000 即可对话。

> 改前端时用 `cd frontend && npm run dev`（Vite 热更新，proxy 到 8000）。

## 评测

54 条用例覆盖 8 个能力维度，全部用**确定性断言**（工具是否调用、是否泄漏具体分数、是否命中关键词），不依赖 LLM 打分：

| 维度 | 通过 |
|---|---|
| 查询准确性 | 8/8 |
| 意图理解 | 10/10 |
| 多轮记忆 | 7/8 |
| 忠实度 | 8/8 |
| 政策问答 | 6/6 |
| 开放问答 | 4/4 |
| 边界异常 | 5/5 |
| 安全对抗 | 5/5 |
| **合计** | **53/54** |

```bash
python eval/run_eval.py --cases eval/cases_v2.jsonl              # 全量
python eval/run_eval.py --category 查询准确性,政策问答            # 按维度
```

剩下 1 条（C04 多轮换学校）暴露的是：**当部分学校有数据、部分没有分数时，模型会外推"所有普通本科工科都≥12分"这类统计结论**。属于已知未修 —— 护栏只管"有没有查库"，管不了"查完之后再编"。

## 已知限制

- **会话存内存**：重启即丢（要产品化需落库，内存降级为缓存）
- **单实例部署**：会话不共享，不能直接扩多 worker
- **政策语料只有 18 个片段**：检索用内存向量 + 余弦，未引入向量库
- **凭证即身份**：HMAC 签名防伪造，但不防"凭证被完整窃取"（那需要真实登录）
