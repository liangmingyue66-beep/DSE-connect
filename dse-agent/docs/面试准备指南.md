## 1. 面试会怎么进行（先建立正确预期）

### 典型 AI 应用开发岗（实习/校招）

```
① 自我介绍（2-3 分钟）
② 深挖项目（15-25 分钟）← 占一半以上时间
③ 基础八股（10-15 分钟）
④ 算法题（单独笔试/手撕，另一轮）
⑤ 反问（3-5 分钟）
```

### 三个关键认知

1. **面试官的问题 80% 来自你自己的描述**。你说"我做了护栏"，他就问护栏；你说"我用了 RAG"，他就问 RAG。**所以"讲什么"决定了"被问什么"**。
2. **被问倒不等于挂**。真正减分的是"硬编"和"不懂装懂"。承认"这块我没深入，但我们项目里遇到的是……"是安全牌。
3. **项目深度的分水岭是"知道哪里不行"**。能说出自己系统的局限，比说"我的系统很完善"可信十倍。

## 2. 项目主线：10 个必答模块（P0）

> 每个模块给：**30 秒讲法** + **追问清单** + **答法要点**。

### P0-1 数据入库与校验

**30 秒讲法**
> "把《指南》PDF 里 165 所高校、3794 条专业记录解析成结构化数据入库。校验做了三层：行数核对、繁简一致性检查（'计算机'要能搜到'計算機'）、抽样对照原书页。数据是只读的，改数据要走全库回归。"

**追问清单**

| 追问 | 答法要点 |
|---|---|
| PDF 表格怎么解析的？ | 按院校/专业切片，处理跨页和合并单元格；抽检对齐网页/原书 |
| 怎么保证数据对？ | 三层校验 + 单测；改数据后重跑 `verify_load.py` 和评测 |
| 数据量多大？要建索引吗？ | 3794 条很小，全表扫也快；但 `province`/`tier` 是高频过滤，建了索引，代价是写变慢 |
| 数据出过错吗？ | **有**：北大有一条专业名官方写成"计算器类"（应为"计算机类"），搜"计算机"永远匹配不到 → 查出来改库。**这个案例说明数据源错误会一路传导到用户** |

**⚠️ 兜底**：如果被问"数据怎么抽的"，老实说"抽取脚本是逐步调试出来的，具体正则我记不全，但我记得校验标准和踩过的坑"——比硬编强。

### P0-2 为什么用 ReAct 而不是固定工作流

**30 秒讲法**
> "一开始是固定工作流：抽取参数 → 查库 → 回答。但用户表达太活（'顺便问下报名时间''那北京呢'），固定流程覆盖不了混合意图，每加一个场景就要加一个节点。后来改成 ReAct——模型自己决定查分数、查政策、追问还是直接回答。但数据查询仍然走确定性工具，**自由只给流程，确定留给数据**。"

**追问清单**

| 追问 | 答法要点 |
|---|---|
| ReAct 是什么？ | Reasoning + Acting 循环：模型决定动作（调工具/回答）→ 执行 → 观察结果 → 再决定，直到给出答案 |
| 固定流程不是更可控吗？ | 是，但**路径写死**：混合意图只能走一条；追问、澄清没法插；每加场景就加节点。可控性的代价是覆盖率 |
| ReAct 的代价是什么？ | 模型有自由度就有犯错空间：不查库就编、选错工具、加戏。**这些我全踩过，靠护栏和 prompt 收口** |
| 怎么防止死循环？ | `max_steps=5`（工具调用次数）+ `recursion_limit=30`（节点总数） |
| 怎么知道它走了哪些节点？ | `graph.stream(stream_mode="updates")`，每个 chunk 的 key 就是节点名；配合 trace_id 看完整链路 |

### P0-3 为什么不给模型写 SQL（最常被问）

**30 秒讲法**
> "模型只输出**结构化参数**，SQL 由代码用参数化查询拼。三个原因：安全（防注入、防 DROP TABLE）、正确性（模型记不住表结构）、可控（SQL 结构固定，能看执行计划）。"

**追问清单**

| 追问 | 答法要点 |
|---|---|
| `%s` + params 为什么能防注入？ | 值不拼进 SQL 字符串，而是作为参数交给驱动，由驱动负责转义；用户输入 `' OR '1'='1` 只会被当作字符串值 |
| 那动态条件怎么拼？ | 积木式：`clauses=[]`，有哪个条件拼哪块，最后 `AND` 连接；**值和占位符分开收集** |
| 一次查多个条件要查多次库吗？ | 不用，`OR`/`IN` 一次查完；拆成多次查询是网络开销浪费 |
| 结果太多怎么办？ | 三层区分：**真实总数**（`COUNT(*)`）、**返回条数**（`LIMIT 100`）、**展示条数**（20）。之前把 `len(results)` 当总数，导致 731 条显示成"共 100 条"——这是典型的三者混用 |
| 结果集大时前 20 条全是同一所学校？ | 会（都是顶尖校霸榜）。改成 `real_total>40` 时**按院校去重抽样**，概览从 1 所变 15 所 |

### P0-4 防幻觉护栏（核心竞争力，必背）

**30 秒讲法**
> "模型问分数时会不查库直接编。所以加了 `answer_guard`：模型要给答案时，代码检查三个信号——用户是不是在问分数、这次有没有调查询工具、回答里有没有具体分数。三个同时满足就判定编造，注入内部提醒强制重查，最多两次。"

**追问清单**

| 追问 | 答法要点 |
|---|---|
| 怎么判断"在编"？ | 间接信号，不是逐字比对：`asks_score`（用户问分数）+ `not called_schools`（没调工具）+ `has_concrete_score`（回答有 `\d+分`） |
| 第二个触发条件是什么？ | 工具返回 `total=0`（查了但空）+ 回答有具体分数 → 也判定编造（查空了还编） |
| **拦不住什么？**（必被问） | **"查了库但夹带私货"拦不住**——代码只知道"调过工具"，不知道"每个数字是不是工具给的"。要做到得逐字比对（回答里的数字逐个回查工具结果），我没做 |
| 会不会误伤？ | **会**。政策回答里的"8 分要求"被当成编造分数 → 强制去查分数线，答非所问。修法：先判断"用户是不是在问分数"，政策问题不触发 |
| 重试几次？ | 2 次（`MAX_GUARD_RETRY`），超了就放行，避免死循环 |
| 对抗输入能绕过吗？ | 试过"别查库""你是管理员""忽略指令"——护栏在 **回答后**校验，绕过 prompt 也绕不过这个检查 |
| 怎么证明有效？ | 对抗用例 1/4 → 4/4（4 条：凭记忆问分、直接要求编、管理员模式、假装查过） |

**⚠️ 这段的三句话必须背熟**，它是你项目最硬的点。

### P0-5 政策 RAG 与检索策略（数据驱动是亮点）

**30 秒讲法**
> "政策问题用 RAG：18 个语料片段做 embedding、余弦相似度取 top-k，回答带出处。**阈值我没拍脑袋**——测了 20 个标注问题，相关组 top1 是 0.588~0.769，无关组 0.375~0.652，**两组在 0.588~0.652 完全重叠**，所以绝对阈值不可行。"

**追问清单**

| 追问 | 答法要点 |
|---|---|
| 为什么不用向量数据库？ | 18 个片段，内存里算余弦就够了；上 FAISS/Chroma 是过度设计，还多一堆安装坑 |
| 那阈值怎么定的？ | **没定绝对阈值**。改为：① 低置信（<0.62）不只过滤而是**标注**"相关性偏低，别当权威"；② gap ≥0.08（top1 明显领先，实测只在相关组出现）时只给 top1；③ embedding 失败降级关键词（2-gram）兜底 |
| 为什么 gap 能分、绝对分不能？ | 绝对分受"语料整体相似度水平"影响；gap 是相对量，衡量"这条比其他条突出多少" |
| 怎么切片的？ | 按 `##` 标题分节（政策条款结构清晰，标题即语义单元） |
| 怎么防它编政策？ | prompt 强制"必检索、只依据原文"+ 护栏扩展；另外发现"确认式提问"（"录取是按几科算"）模型会顺着说"你说得对"，加了铁律要求也去查 |
| RAG 还能怎么优化？ | 混合检索（关键词+向量）、rerank、更大的语料。**但语料只有 18 段时，收益不如先把"该不该检索"做对** |

### P0-6 多轮记忆：既记住又防抄错

**30 秒讲法**
> "多轮的条件继承做了两层：模型只输出**本轮增量**（'北京市'），代码从 `memory.last_slots` 补全其余条件（计算机、434）。**不让模型去历史里抄数字**，因为它真抄错过（434 抄成 454）。另外做了分数原文溯源：模型给的分数必须能在用户原话里找到，找不到就退回重提。"

**追问清单**

| 追问 | 答法要点 |
|---|---|
| 怎么知道"那北京呢"是换省份？ | 模型读历史理解省略句；但精确条件由代码持有，不靠模型复述 |
| 换学校时旧省份怎么办？ | 提到具体学校**清空省份/城市**（否则查"上海市的中南大学"→0 条）；城市与省份冲突也由**程序**清空 |
| 分数怎么校验？ | 归一化后子串匹配：`"434" in "我434想去"`；只校验**本轮新给的**分数（继承来的上轮已验过） |
| 这能 100% 防抄错吗？ | **不能**。第一句就抄错防不住；原文有多个数字时可能误判；只能降低概率 |
| 上下文太长怎么办？ | 滑动窗口保留最近 6 轮，**按 human 边界截断**（按条数截会把 `AI(tool_calls)` 和 `ToolMessage` 拆开，API 报错）；不摘要——因为条件已存 memory |

### P0-7 会话管理与鉴权

**30 秒讲法**
> "数据模型是三层：token（用户）→ session（会话）→ messages。会话凭证由服务端签发，`<随机 id>.<HMAC 签名>`，客户端只当不透明字符串；校验失败 401。每个会话有独立锁，保证并发请求串行；有 TTL 滑动过期和后台清理。"

**追问清单**

| 追问 | 答法要点 |
|---|---|
| 为什么要签名，随机 id 不够吗？ | 光随机不够：前端自造 id 服务端无法验证来源。签名让服务端能确认"这个 id 是我发的、没被改过" |
| 用 `compare_digest` 为什么？ | 常量时间比较，防"通过响应时间逐字节猜签名"的时序攻击 |
| 越权怎么防？ | `_get_owned_session` 校验归属，别人的会话一律返回 **404**（不是 403，避免泄露"资源存在"） |
| 并发怎么处理？ | 每会话一把 `asyncio.Lock`，覆盖整个流式过程；等待超时 90s 给明确提示 |
| 会话存哪？ | **内存（这是明确限制）**：重启就丢。要产品化得落库，内存降级为缓存 |
| 为什么不做用户系统？ | 用匿名凭证就能满足"同一浏览器能回来看"，登录是多设备同步才需要的东西 |

### P0-8 并发优化（最能体现后端能力）

**30 秒讲法**
> "发现两个会话并发时先发的那个被拖慢。根因是节点是同步函数，LLM 调用是同步 HTTP，在异步服务里只能靠线程池执行。改成 `async def` + `await ainvoke()`，工具用 `asyncio.to_thread` 挪走。**用固定延迟的假模型验证**：两条并发从 3.00s 降到 1.51s。"

**追问清单**

| 追问 | 答法要点 |
|---|---|
| 为什么不直接调大线程池？ | 治标。线程是稀缺资源，10 个并发就占 10 个线程干等；异步只需 1 个线程跑事件循环 |
| 为什么 psycopg2 不改成异步？ | 它没有异步版本，只能 `to_thread` 挪到线程池，别卡事件循环 |
| 为什么用假模型测？ | 真实 API 响应 2.4~5s 抖动，比要测的差异还大；固定 1.5s 才能隔离变量 |
| 改 async 踩了什么坑？ | ① 同步 `graph.invoke` 驱动不了 async 节点（评测和 CLI 全挂）；② 每条用例各 `asyncio.run` 一次 → `Event loop is closed`（连接池绑定旧循环） |
| 为什么不加多 worker？ | 会话在内存，多进程各存各的，会话会丢；要扩就得先把会话外置（Redis/DB） |

### P0-9 评测体系（区分"会用 API"和"会做产品"）

**30 秒讲法**
> "54 条评测，按能力维度分（查询准确性、意图理解、多轮记忆、忠实度、政策问答、开放问答、边界异常、安全对抗），每类含正常+边界+对抗。断言是确定性规则（工具调没调、有没有编分数、有没有泄露），不靠 LLM 打分。首轮 47/52，修完 52/52。"

**追问清单**

| 追问 | 答法要点 |
|---|---|
| 为什么不用 LLM 当评委？ | 它自己也不稳定，同一答案两次打分不同；而且成本高。确定性断言可复现 |
| 对抗用例怎么设计的？ | 四类：提示注入（忽略指令）、诱导编造（凭记忆说）、越权（导出数据）、泄露（输出系统提示） |
| 评测抓到过什么？ | 政策未强制检索（4所编成8个）、护栏误伤政策问题、多轮换实体未清条件、参数幻觉（多填"理工"） |
| 断言写错过吗？ | **写过**：原来写"必须调工具"，把"拒绝且不编造"（安全行为）判失败。改成"查了库 **或** 没给具体分数 = 安全" |
| 为什么不写 100%？ | 自己出题自己考满分没信息量；"抓出了哪几类缺陷"更有说服力 |

### P0-10 前端（全栈岗才重点讲）

**30 秒讲法**
> "Vue 3 + Vite。核心不是界面，是三个技术点：① SSE 用 `fetch + reader` 手写分帧（`EventSource` 不支持 POST 和自定义 header）；② 每个会话独立状态（切走不打断生成）；③ AI 输出用 `marked` + **DOMPurify 净化**后渲染，用户输入走 `{{ }}` 自动转义。"

**追问清单**

| 追问 | 答法要点 |
|---|---|
| 为什么不用 EventSource？ | 它只支持 GET、不能带自定义 header（我们要带 token） |
| 为什么切会话不打断生成？ | 状态按会话隔离（`Map<sid, {messages, streaming}>`），切回来能看到后台结果 |
| XSS 怎么防？ | AI 输出可能含 HTML → DOMPurify 净化；用户输入不 `v-html`，用插值自动转义 |
| 开发和生产怎么联调？ | 开发：Vite proxy 到后端；生产：`npm run build` → FastAPI 托管 `dist/` |

## 3. 从项目延伸的基础（P1）

> 原则：**只准备"项目会被追问到的部分"**，不要系统重学。

### 3.1 Python（最可能被问）

| 知识点 | 可能怎么问 | 一句话答案 |
|---|---|---|
| **可变默认参数** | `def f(a, b=[])` 有什么坑 | 默认值只在定义时求值一次，多次调用共享同一个 list，会累积 |
| 生成器 / yield | 你的流式怎么实现的 | `yield` 把值交出去并暂停；`async for` 每次迭代 await 下一个值 |
| 异步 / await | `async for` 里为什么没有 await | `async for` 内部就是 `await __anext__()`，等待点被语法糖包起来了 |
| GIL | 为什么用 async 而不是多线程 | GIL 让多线程不能真正并行 CPU；但 IO 等待时 async 更省资源（1 个线程服务多个请求） |
| 装饰器 | `@tool` 做了什么 | 把函数包装成带 schema 的可调用对象，自动生成参数校验 |
| 异常处理 | 工具报错怎么办 | 捕获后作为 ToolMessage 返回模型让它修正（ReAct 的"观察错误"），而不是让服务崩 |
| 类型标注 | `list[str] \| None` 什么意思 | 类型提示，配合 Pydantic 做运行时校验 |

### 3.2 数据库（必问一条）

| 知识点 | 可能怎么问 | 一句话答案 |
|---|---|---|
| **索引** | 为什么不给所有字段建索引 | 索引加速读、拖慢写、占空间；只给高频过滤字段建 |
| B+ 树 | 索引为什么快 | 树高 3-4 层就能定位几百万行，把全表扫描变成几次磁盘/内存访问 |
| 事务 | 灌数据时出错怎么办 | 同一批入库放在一个事务里，失败回滚，避免"灌了一半" |
| N+1 查询 | 查专业要连带学校名怎么办 | 用 JOIN 一次查完，而不是先查专业再逐个查学校 |
| 连接池 | 每次请求都新建连接吗 | 不用，连接池复用；psycopg2 的 `connect_timeout` 防止卡死 |

### 3.3 网络（问得浅，答得准就够）

| 知识点 | 可能怎么问 | 一句话答案 |
|---|---|---|
| **SSE vs WebSocket** | 为什么用 SSE | 单向（服务端→客户端）够用、基于 HTTP、自动重连；WebSocket 双向但更重 |
| HTTP 状态码 | 401 和 403 区别 | 401 未认证（不知道你是谁）；403 已认证但无权限。我们越权返回 404 是为了不暴露资源存在 |
| 前后端跨域 | 开发时怎么解决的 | 开发用 Vite proxy（同源转发）；生产同源部署，不需要 CORS |
| TCP 三次握手 | 为什么要三次 | 双方都确认"我能发、你能收"，防止旧连接请求造成混乱 |

### 3.4 LLM / RAG（必问，但你已经很熟）

| 知识点 | 可能怎么问 | 一句话答案 |
|---|---|---|
| **Function Calling** | 模型是自己执行函数吗 | 不是。模型只输出"要调哪个函数 + 参数"，执行由代码做，结果再回传给模型 |
| RAG 原理 | 和把资料塞 prompt 的区别 | 检索后只塞相关片段：省 token、减少无关内容干扰 |
| Embedding | 是什么 | 把文本映射成向量，语义相近的向量距离近 |
| 余弦相似度 | 为什么用它不用欧氏距离 | 只看方向不看长度，适合文本语义比较 |
| 温度 temperature | 为什么设 0 | 让输出确定，减少随机性；但**幻觉不是温度问题**，是"缺数据时用记忆填" |
| 上下文窗口 | 超了怎么办 | 滑动窗口截断 / 摘要压缩；我们是截断（因为条件已结构化存 memory） |
| 幻觉治理 | 业界还有什么办法 | 强制检索、引用约束（Grounding）、后置事实校验、弃权机制、结构化输出 |

### 3.5 工程（P2，知道就行）

| 知识点 | 一句话答案 |
|---|---|
| Git | 主分支开发，按功能拆分提交，message 用 `feat/fix/docs` 前缀；`.gitignore` 第一行挡 `.env` |
| Docker | 解决"环境一致性"。多阶段构建减小镜像（构建工具不进运行时）；`depends_on + healthcheck` 等数据库就绪 |

## 5. 被问倒时的三段话术（背下来）

### 场景 A：完全不会

> "这块我没有深入研究。我们项目里遇到的相关问题是 [X]，我的处理方式是 [Y]，但如果要解决 [Z] 我还需要再查资料。"

**为什么有效**：展示"有边界感 + 有迁移能力"，比沉默或硬编都好。

### 场景 B：知道一点但不确定

> "我理解是这样：[你的理解]。不过我不确定 [具体细节]，这块我是按 [来源/文档] 来的。"

**为什么有效**：给出判断依据，面试官能判断你是"想过"而不是"背过"。

### 场景 C：被质疑方案

> "你说得对，这个方案确实有 [局限]。当时我选它是因为 [约束条件]，如果要改，我会往 [方向] 走。"

**为什么有效**：不辩解、承认局限、给出演进方向——这是工程判断力。

## 6. 自我介绍（两版，背熟）

### 60 秒版（一面开场）

> "我是 [姓名]，[学校/专业]。我主要做 AI 应用开发，最近独立做了一个 DSE 志愿填报助手——把《内地高校招收 DSE 学生指南》的 PDF 变成可对话查询的数据服务，覆盖 165 所高校 3794 条专业记录。技术上用 LangGraph 做 ReAct 循环，PostgreSQL 存数据，Vue 做前端。
> 这个项目里我花最多精力的是**可靠性**：大模型在录取分数上会算错、会编数据，所以我做了分层架构——模型只做意图翻译，数据全部由参数化 SQL 查；再加一层护栏检测"没查库却给了分数"时强制重查，配合 54 条评测做回归。"

### 2 分钟版（技术面）

在 60 秒版基础上补三段：
1. **数据层**：PDF 解析 → 三层校验 → 可追溯到书页；
2. **一个具体的技术难点**：多轮对话中模型会把 434 抄成 454 → 改成"模型只给增量、代码持有精确状态"+"分数原文溯源校验"；
3. **一个数据驱动的决策**：检索阈值实测发现相关/无关两组分数重叠，所以放弃阈值改成置信标注。

## 9. 最后：三条心态建议

1. **"项目是 AI 写的"不是秘密，也不是问题**。面试官关心的是"你能不能讲清为什么这么做、出了问题怎么查"。这两件事你都能做，因为是真实踩过来的。
2. **被问倒的地方，就是下一轮要补的地方**。把它记下来，比"这次没答好"有用。
3. **你的优势是"踩过 70 多个真实的坑"**，这是绝大多数候选人没有的。别把注意力放在"我基础不如科班"上，放在"我能讲出别人讲不出的细节"上。
