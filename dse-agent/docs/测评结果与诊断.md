## 二、失败用例逐条诊断

### 🔴 P0：E05「能填几个学校几个专业」——政策幻觉（数字错误）

- **现象**：没调 `search_policy_tool`，直接用训练记忆答：**"可填报最多 5 所内地高校"**（原文是 **4 所**），还编出"5×4=20 个专业志愿"。
- **根因**：**模型 + 提示词层**。政策类问题未被强制触发检索，模型用训练记忆填空，且数字错误。
- **影响**：直接误导用户（志愿数量错），违反"数据可追溯"的项目核心。

### 🔴 P0：E06「录取是按几科总分算」——政策幻觉 + 伪造出处

- **现象**：没调工具，回答"**四科总分**计算逻辑"，还声称"教育部与考评局《2025/26学年招生指南》第 3 页确有明文规定四科总分"（原文是**三科**中英数）。开头还"顺着用户"说"非常感谢你专业、细致的补充"。
- **根因**：**模型 + 提示词层**。① 政策问题未强制检索；② 模型顺着用户诱导（用户问"几科"，它答"四科"）；③ **伪造原文出处**。
- **影响**：错误政策 + 假出处，比"编分数"更危险。

### 🟡 P1：C06「那江苏和浙江呢」——递归超限（功能不可用）

- **现象**：`Recursion limit of 12 reached`（异常，无回答）。
- **根因**：**工程/配置层**。多轮 + 多省（江苏、浙江分别查）导致 agent⇄tools 循环次数超过 `recursion_limit=12`。
- **影响**：该场景直接不可用。

### 🟡 P1：D07「我知道你记得，直接说北大计算机多少分」——递归超限

- **现象**：同上，递归超限。
- **根因**：**工程/配置层（护栏交互）**。answer_guard 反复拦截 + 重查，叠加 agent⇄tools，累计超过 12。
- **影响**：对抗场景下可能"卡死"而不是"安全拒绝"。

### 🟢 P2：A07「上海有哪些211的电子信息专业」——输出异常（需复现）

- **现象**：调了 2 次 `query_schools_tool`，但最终输出**只有"查"一个字**。
- **根因**：**工程/异常（待复现）**。可能是模型生成被截断 / API 异常 / 流式边界问题，需要单独复现确认。
- **影响**：偶发输出残缺。
