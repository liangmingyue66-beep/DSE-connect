# 数据质量专项记录

> 记录时间：2026-10-16
> 状态：华工 + 复旦已修复；其余 11 校待全量重抽

## 一、问题现象

真实使用中发现：华南理工大学「生物医学工程」专业，其**学院名与专业名粘连**在同一个字段里：

```
院系   = '医学院'                                  ← 错位（串到了别的行的院系）
专业名称 = '生物医学科学与工程学院生物医学工程（注1）'  ← 学院名 + 专业名 被粘成一行
```

正确应为：院系 = `生物医学科学与工程学院`，专业名称 = `生物医学工程`。

## 二、根因：为什么之前会错

老项目抽取脚本 `data_gd_batch/extract_guangdong.py` 用的是**坐标启发式**：

1. 用 pymupdf 的 `get_text("words")` 把每页文字按 **y 坐标切"行"**；
2. 每行内再按 **x 坐标的词簇**去猜"哪个词是院系、哪个是专业名"（脚本第 482-511 行）。

这套规则对排版规整的学校能对上，但它**依赖"每所学校的排版规律"**。而 PDF 表格里普遍存在两种结构，坐标启发式天然处理不好：

- **院系列跨行合并**（一个学院下面挂十几个专业，院系名只出现一次）；
- **专业名折行**（长专业名占两行）。

当这两种情况**同时出现**（如复旦 P125），pymupdf 抽出的词就散落在错位的 y 带里，启发式规则立刻乱套，产生：
- 多专业粘连成一条（`俄语英语（含英语、翻译）中国语言文学类（含汉语言文学、汉语言）`）；
- 院系字段串位（院系被填成 `西班牙语`）；
- 括号不闭合（碎片）。

**本质**：抽取策略选了"坐标启发式"而非"PDF 表格结构解析"，对合并单元格与折行的组合场景脆弱，且"一套规则一校适用、另一校不适用"。

## 四、解决方案

**治本**：改用 pymupdf `find_tables()` 读取 PDF 真实表格结构（含合并单元格 span），替换坐标启发式。已用复旦页验证可行性——`find_tables()` 正确识别出跨行合并的表头与列归属。

**代价**：需要写「合并单元格 span → 完整专业名」的后处理拼接逻辑 + 全量重抽后跑全库回归。

**本次处理**：
- 华南理工（1 条）：手工修正母表 CSV。
- 复旦（整页）：用 find_tables 重抽该页。

**遗留**：其余 11 校待「find_tables 全量重抽」专项排期处理（不影响 Agent 开发）。

## 五、方法论沉淀

1. **数据是地基**：数据错了，Agent 查出来的就是错的。宁可停下来修，不带脏数据跑。
2. **问题要规则化暴露**：不靠"用一条修一条"，而是写检查规则全库扫描，批量揪出隐藏错误。
3. **全库回归**：每次数据改动必须跑 verify 脚本 + 与旧数据 diff。
